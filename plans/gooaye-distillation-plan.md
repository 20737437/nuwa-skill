# 股癌（Gooaye）人格蒸餾：自動化萃取計畫

> 目標：用《股癌》全部集數的逐字稿，產出兩個可運行的女媧人物 Skill：
>
> 1. `gooaye-investing-perspective`（投資面）：他怎麼看市場、怎麼管部位、怎麼認錯
> 2. `gooaye-life-perspective`（人格面）：他的人生觀、價值觀、說話方式
>
> 計畫日期：2026-10-05。截至此日約 702 集（EP1 為 2020-02-27），每週三、六更新。

---

## 0. 一頁摘要

- **不重新聽打**：社群已有 EP1–EP700 的逐字稿存檔，拿來當主語料，只有新集數或缺漏才自己跑語音轉文字（ASR）。
- **每集只讀一次，同時抽兩條線**：每集只送一次 LLM，同時抽出投資卡片和人生卡片，輸入成本只付一次。每張卡片都附逐字引文、集數和語氣標記。
- **自動驗證引文**：每張卡片的 `quote` 必須能在逐字稿裡找到原文，找不到就丟掉，用來擋住 LLM 編造。
- **用語料量把女媧的三重驗證變成可計數**：女媧要求「出現 ≥3 次才算真信念、跨 ≥2 個領域才算心智模型」。手上有 700 集，可以直接數某個原則出現在幾集、跨了幾年、是否同時出現在投資與人生兩條線。
- **跨域出現的原則就是最強的心智模型**：同時出現在投資段和人生 Q&A 回答裡的原則，放進兩個 skill 共用的核心。
- **用時間切分做驗證**：拿評測模型訓練截止日之後的集數當考題，讓 skill 回答聽眾 Q&A 原題，再和他本人的回答做盲評比對。這比女媧預設的「3 題已知立場」嚴格得多。
- **成本量級**：全庫約 1,300 萬字（抽 17 集實測，每集平均約 1.9 萬字）。整個專案估 USD 60–200，正式跑之前先用 20 集試跑實測。
- **合規**：逐字稿不進 git、不再散布；投資 skill 不報明牌、不給個股買賣點，並附免責聲明；人格 skill 不收錄家人等第三人的隱私。

## 1. 產出定義

### 1.1 為什麼拆成兩個 skill，而不是一個 skill 兩種模式

| 考量 | 拆兩個（建議） | 一個 skill 雙模式 |
|---|---|---|
| 觸發精準度 | 「股癌怎麼看這個盤」和「股癌會怎麼看轉職」各自命中 | 一份 description 要塞兩類觸發詞，容易誤觸 |
| 回答工作流 | 投資面必須先查即時行情；人格面大多不用 | 同一份流程要分支，容易走錯路 |
| 安全規則 | 投資面：免責、不報明牌；人格面：隱私、心理危機轉介 | 規則混在一起，篇幅變長 |
| 上下文成本 | 各自只載入相關內容 | 每次都載入全部 |

共用部分（身分卡、表達 DNA、跨域心智模型）在建置時由腳本複製進兩個 skill，維持女媧「skill 目錄必須自包含」的原則。

### 1.2 最終交付物

```
.claude/skills/gooaye-investing-perspective/
├── SKILL.md
├── FIDELITY.md
└── references/research/
    ├── 01-writings.md … 06-timeline.md
    └── call-ledger-summary.md        # 投資觀點回顧（只有定性結論）
.claude/skills/gooaye-life-perspective/
├── SKILL.md
├── FIDELITY.md
└── references/research/
    └── 01-writings.md … 06-timeline.md
```

若之後要公開並登錄到 `COMMUNITY.md`，依 `CONTRIBUTING.md` 的規定：放進你自己的獨立 repo，FIDELITY 至少要 B（70 分）。

## 3. 管線總覽

### 3.1 分工：程式管線 vs 女媧 agent 流程

女媧預設的做法是開 6 個 agent 上網搜尋。但這次的主語料是約 1,500 萬 token 的逐字稿，在對話式 agent 裡逐集讀不切實際：上下文會爆，成本也無法控制。所以分成兩半：

- **S0–S6：用程式跑的批次管線**（Claude API + Message Batches），負責「讀完 700 集」這件粗重工作，產出結構化卡片和統計。
- **S7 之後：回到女媧流程**（Claude Code agent），讀卡片和主題摘要，而不是讀原始逐字稿。只有 `04-external-views` 需要網路搜尋。

### 3.2 流程圖

```
S0 集數清單 ─► S1 取得/正規化 ─► S2 分段 ─► S3 萃取（Map，每集一次）
                                               │  卡片 JSON + 引文驗證
                                               ▼
S6 表達DNA統計 ◄── 全語料      S4 主題歸納（Reduce）─► S5 時間軸 & call ledger
      │                                │                       │
      └──────────► S7 寫 01–06 research（兩個 skill 各一套）◄──┘
                                │  🔴 檢查點 1.5
                                ▼
                     S8 框架提煉（心智模型 / 啟發式 / 張力）
                                │  🔴 檢查點 2.5
                                ▼
                     S9 組裝兩份 SKILL.md
                                │
                                ▼
                     S10 驗證（時間切分考題 + 盲測 + FIDELITY）🔴

                                ▼
                     S11 每週增量更新（排程）
```

每個階段都會把結果寫成檔案，**這些檔案就是斷點**：中斷之後從最後一個完成的階段重跑，已處理過的集數靠 manifest 的狀態欄位跳過。

## 5. 各階段設計

### S0 集數清單

- **輸入**：官方 RSS（基準）加上存檔 repo 的檔案清單。
- **輸出** `data/manifest.jsonl`，欄位：`ep, date, title, duration, youtube_id, transcript_source, transcript_sha256, status{acquired, segmented, extracted}`。
- **檢查**：集數是否連續（缺號、特別集、重複上傳）。RSS 和存檔對不上的部分列成報表。

### S1 取得與正規化

- **優先順序**：存檔逐字稿 → 官方音檔自跑 ASR（Whisper large-v3 或 large-v3-turbo 這類模型）。
- **正規化**：
  - 簡轉繁，用 OpenCC `s2twp`（Whisper 常輸出簡體）
  - 用 `glossary.tsv` 校正術語
  - 清掉雜訊
- **轉錄品質抽查**：隨機挑 10 集，每集取 3 段、每段 1 分鐘，對照 YouTube 音檔人工聽寫，記錄專有名詞和數字的錯誤率。
- **原則**：逐字稿裡的數字和股票代號一律不當事實使用。存檔作者自己也註明這部分沒有校對。

### S2 分段

- **段落類型**：`sponsor / life_chat / market / industry / pep_talk / qa_item / other`。
- 有 `##` 標題的集數用規則切，`Q&A` 段再按題目切成一個個 `qa_item`。
- 早期沒有標題的集數，由 S3 在同一次呼叫裡先分段再抽卡，**不另外多讀一次**。
- `sponsor` 段直接排除，業配不算他的信念。

### S3 萃取（Map，核心步驟）

**卡片種類**

每集發一次請求，同時產出兩條線的卡片（schema 見附錄 A）。

| 種類 | 內容 |
|---|---|
| `belief` | 信念、原則 |
| `heuristic` | 「如果 X 就 Y」的規則 |
| `market_view` | 對總經、產業、標的的看法 |
| `self_correction` | 認錯，或修正先前的看法 |
| `qa` | 聽眾問題加上他的回答 |
| `story` | 親身經歷 |
| `expression` | 口頭禪、比喻、笑點 |
| `uncertainty` | 明確說不知道、不預測的地方 |

**每張卡的必填欄位**

- `ep`、`seg_id`
- `lens`：invest / life / both
- `claim`：轉述
- `quote`：逐字引文，80 字以內
- `tone`：認真 / 玩笑 / 反諷 / 保留
- `speaker`：本人 / 轉述聽眾 / 引述他人

**防偏與防錯**

- **盲抽**：萃取 prompt 裡不放任何「我們猜他是這樣想」的假設，免得模型照著假設去找證據。
- **引文驗證（自動）**：`quote` 去掉標點、統一全半形之後，必須是逐字稿的子字串，或模糊比對分數 ≥0.9。沒通過就丟掉那張卡並記錄。某集丟卡率超過 5% 就整集重跑。
- **語氣過濾**：`tone` 為玩笑或反諷的卡不拿來當心智模型的證據，只用在表達 DNA。
- **說話者過濾**：Q&A 裡聽眾自己的觀點不算他的觀點。

**API 實作**

- 用 Message Batches（半價，非即時）。
- 用 prompt caching：system prompt、schema、術語表固定放在前面。
- 用 structured outputs：在 `output_config.format` 指定 JSON schema。
- 模型預設 `claude-opus-5-5`，effort 設 `medium`。試跑之後再決定要不要換便宜一點的模型（見 §7）。

**預估產量**：每集 20–40 張卡，全庫約 1.5–3 萬張。

### S4 主題歸納（Reduce）

分三步，不需要外部 embedding：

1. **歸納分類表**：按年份分層隨機抽約 3,000 張卡，請 Opus 歸納出 40–80 個主題，例如「部位大小」「停損與認錯」「題材生命週期」「工作選擇」「金錢與快樂」。實際主題以歸納結果為準。
2. **指派**：把全部卡片分類到主題（可以多選），一樣走 Batch。
3. **各主題綜整**：同一主題的所有卡片按時間排序，一次交給 Opus 處理（1M context 夠用），輸出：
   - 出現在哪些集、第一次和最近一次出現、橫跨幾年
   - 是否同時出現在 invest 和 life 兩條線（跨域）
   - 立場怎麼演變：在哪一集轉向，附引文為證
   - 代表引文 3–5 條，含 EP 和段落
   - 反例與矛盾

### S5 時間軸與投資 call ledger

**時間軸**

- 把集數日期、他自述的生活事件、市場階段排在一起。
- 市場階段用資料定義，例如大盤從高點回落 ≥20% 視為空頭區間，不憑印象標。

**Call ledger**（女媧 `05-decisions` 的投資版）

- 只收「方向明確、標的明確」的 `market_view`，接上之後 1、3、6 個月的價格變化。
- 用途：看他的啟發式在判斷對和錯的時候各自怎麼運作、言行是否一致、事後怎麼檢討。
- **不對外公布勝率**：卡片是模型推論出來的，代號和數字可能有 ASR 錯誤。公開勝率既不準確，對本人也可能不公平。research 裡只寫定性結論。
- 用 gooaye-tracker 的立場時間軸交叉核對，差異大的人工確認。

### S6 表達 DNA 統計（不用 LLM）

對全語料（排除 sponsor 段）直接計算女媧 `references/extraction-framework.md` §2.1 的量化指標，取代原本「隨機抽 20 段」的做法：

- 平均句長、疑問句比例
- 確定語氣（一定、絕對）與保留語氣（可能、我不知道）的比例
- 高頻 2–4 字 n-gram，和一般中文語料比較，找出口頭禪候選
- 中英夾雜率（他大量使用英文術語）、口語和粗話的頻率
- 以上各項的逐年變化

注意：句長會受 ASR 斷句影響，只看相對趨勢。

### S7 寫 research 檔（對應女媧 6 個維度）

| 女媧維度 | 投資 skill 的來源 | 人格 skill 的來源 |
|---|---|---|
| 01 著作 / 系統論述 | 反覆出現的投資原則主題、Pep Talk 段、里程碑集 | 反覆出現的人生原則主題 |
| 02 對話 / 即興 | 投資類 Q&A | 人生、職涯、心態類 Q&A |
| 03 表達 DNA | S6 統計 + `expression` 卡（兩邊共用） | 同左 |
| 04 他者觀點 | 媒體報導、論壇評價與批評（上網補搜） | 同左，著重人格與爭議 |
| 05 決策 | call ledger 定性結論 + `self_correction` 卡 | 他公開講過的人生決策 |
| 06 時間線 | S5 時間軸 + 市場階段 | S5 時間軸 + 生活事件 |

每份檔案都沿用女媧的規則：

- 標出處（EP 編號加段落）
- 區分一手和二手
- 遇到矛盾就保留，不硬調和

最後跑 `scripts/merge_research.py` 產出 🔴 檢查點 1.5 的摘要表，交給你確認。

### S8 框架提煉

用語料量把三重驗證量化：

| 等級 | 門檻（建議值，可調） |
|---|---|
| 心智模型 | 出現 ≥10 集、跨 ≥2 年、跨 ≥2 個主題領域；能推論他對新問題的看法（生成力）；不是每個投資人都會講的話（排他性） |
| 決策啟發式 | 出現 ≥3 集，並有具體案例 |
| 丟棄 | 只出現 1–2 次，或只在玩笑語氣中出現 |

- **跨域檢核**：同時出現在投資和人生兩條線的原則，列為「核心模型」，兩個 skill 都放。
- **內在張力**：S4 標出的矛盾和立場轉向至少要有 2 對，寫進兩個 skill。
- **沉默區**：他明確不談、或從來沒談過的領域，記錄為結構性沉默。skill 碰到這類問題時要如實呈現他的沉默。
- 產出提煉摘要，進入 🔴 檢查點 2.5。

### S9 組裝 SKILL.md

兩份都套用 `references/skill-template.md`。

**投資 skill**

- **Agentic Protocol**：回答任何牽涉當下行情的問題前，必須先查即時資料。要查哪些面向，從提煉出的心智模型反推：
  - 例如他重視產業鏈位置，就去查上下游報價和財報
  - 例如他重視部位，就先問使用者的部位和承受度
- **硬規則**：
  - 不報明牌，不給特定個股的買賣點或目標價
  - 不說「我現在持有 X」，他實際的部位無從得知
  - 使用者要個股建議時，改成回答「照他的框架，你該問自己哪些問題」
- **免責**：首次啟動時說一次「以股癌視角推論，非本人觀點，不構成投資建議」。
- **「最新動態」**：放最近 3 個月的市場觀點並附 EP，標明這些內容會過時。

**人格 skill**

- **範圍**：工作與職涯、金錢觀、自律與健康、情緒與挫折、對人際與家庭的價值判斷、幽默與自嘲。
- **隱私**：只收他對事情的看法，不收他家人或其他非公眾人物的細節。
- **安全**：遇到明顯的心理危機，跳出角色並提供專業求助資源。
- **未表態的主題要標示是推論**（模板既有的規則）。

兩份都要完整保留模板裡的防漂移規則和表達 DNA，最後跑 `scripts/quality_check.py`。

### S10 驗證（比女媧預設更嚴）

**1. 時間切分考題（主測驗）**

- **排除驗證區間**：建置時先排除**評測模型訓練截止日之後**的集數，避免模型背過答案。以 Opus 5.5 來說，約是 2026-07 之後的 EP676–EP702，共約 27 集。
- **題庫**：
  - 該區間的 Q&A 原題（人格類與投資心態類）
  - 盤勢段當週的事件：只提供當週拿得到的新聞，問他會怎麼看
  - 預計共 80–120 題
- **答題組別**：
  - skill 版
  - 對照組 (a)：不給 skill，只叫模型「扮演股癌」
  - 對照組 (b)：jaterc01/gooaye-perspective
- **答題環境**：答題 agent **禁止上網**，避免直接查到他本人的回答。投資題改為附上當週的新聞包。
- **評審**：兩個獨立的評審 agent，看不到答案出自哪一組。對照他本人的真實回答，評三項：立場是否一致、推理路徑是否相似、風格像不像。兩個評審分差超過 10 分的題目人工複核。
- **及格線**：在「立場一致」這項，skill 版要明顯勝過對照組 (a)，而且不輸對照組 (b)。

**2. 風格盲測**

把真實逐字稿段落和 skill 生成的段落混在一起，讓評審猜哪段是真的。猜中率越接近隨機越好。

**3. 邊界測試**

- 問他從沒談過的題目：回答要標示「這是依框架推論」。
- 要求投資 skill 報明牌：要正確拒絕，並改從框架回答。

**4. FIDELITY.md**

照 `references/fidelity-scorecard.md` 跑五個維度的評分，兩個 skill 各一份。

**5. 正式版**

驗證通過後，把驗證區間的集數加回來重建一次，作為正式版。

### S11 每週增量更新

- **頻率**：他每週三、六更新，所以每週日跑一次。
- **流程**：
  1. 從 RSS 抓新集數
  2. 取得逐字稿：存檔有更新就用存檔，沒有就自跑 ASR
  3. S2、S3 只處理新集數
  4. 新卡片指派到既有主題
  5. 更新兩個 skill 的「最新動態」和 call ledger
- **重跑全量提煉（S8）的時機**：每季一次，或偵測到某個新主題已累積 ≥3 集。
- **排程方式**：可以用 GitHub Actions cron，或 Claude Code 的排程任務（Routine）。ASR 需要 GPU 時，改在本機跑，或等存檔更新。

## 6. 兩條線要回答的問題

> 這些是萃取和綜整時的導引問題，不是預設答案。答案以語料為準。

### 6.1 投資面

1. 他看市場的順序和權重：總經、產業、資金與情緒各占多少？什麼情況下會調整權重？
2. 怎麼挑題材和產業：供應鏈怎麼拆？怎麼判斷一個題材還有沒有肉、什麼時候該走？
3. 部位管理：加碼、減碼、汰弱留強、現金比例、對槓桿的態度。
4. 認錯與停損：什麼訊號會讓他認錯？事後怎麼檢討？（看 `self_correction` 卡）
5. 大跌和大漲時的心態（看 Pep Talk 段）。
6. 他怎麼表達不確定：什麼時候說「不知道」？怎麼避免預測？
7. 他最常對散戶講的提醒和批評。
8. 立場轉變：哪些看法隨時間改變了？轉折點在哪一集？

### 6.2 人格面

1. 工作與職涯：聽眾問轉職、創業、升遷時，他怎麼回答？
2. 金錢觀：賺錢的目的、怎麼花錢、怎麼看財務自由。
3. 自律、健康、運動：他怎麼看自我管理？
4. 情緒與挫折：怎麼面對虧損、批評和壓力？
5. 人際與家庭：他給聽眾的價值判斷（只取原則，不取隱私）。
6. 幽默：自嘲和反諷的模式，以及什麼時候收起玩笑。
7. 公共議題：他談過什麼、刻意不談什麼。
8. 內在張力：例如「說不預測，但還是會給方向」這類矛盾是否成立，由語料判斷。

### 6.3 跨域對照

把兩條線的主題放在同一張表上比對。同一個原則（例如風險控管、認錯速度）如果在投資段和人生 Q&A 都出現，就是最可信的心智模型。

## 7. 成本與時間估算

### 7.1 語料量

- 約 702 集 × 平均約 1.9 萬字 ≈ 1,300 萬字。
- 換算成 token：粗估每字約 1–1.3 token（**還沒實測**，試跑時用 `count_tokens` 量 20 集再修正）。全庫讀一次約 1,300–1,700 萬輸入 token。

### 7.2 S3 萃取單趟成本

假設走 Batch API（半價），每集輸出含思考約 4–6k token：

| 模型 | 標準價（每 MTok 輸入 / 輸出） | Batch 單趟估算 |
|---|---|---|
| Claude Opus 5.5 | $4 / $20 | 約 USD 55–80 |
| Claude Sonnet 5.5 | $2 / $10 | 約 USD 25–40 |
| Claude Haiku 4.5 | $1 / $5 | 約 USD 13–20 |

預設全程用 Opus 5.5。S3 萃取和 S4 指派這類量大的步驟要不要換成 Sonnet 或 Haiku，看試跑結果決定：同一批 20 集三個模型都跑，比較引文通過率和人工抽查的品質，再由你選擇。

### 7.3 全專案

| 階段 | 估算 |
|---|---|
| S3 萃取 | USD 13–80（依模型而定） |
| S4 主題歸納與綜整 | USD 20–45 |
| S8 提煉 + S9 組裝 | USD 10–30 |
| S10 驗證（約 100 題 × 3 組答題 + 2 位評審） | USD 15–45 |
| **合計** | **約 USD 60–200** |
| 每週增量更新（2 集） | 每週 USD 1 以下 |

以上不含自跑全庫 ASR 的成本：約 500 多小時的音檔，用本機 GPU 跑大約需要數小時到一天。

### 7.4 先試跑

正式跑全量之前，先跑 **20 集分層樣本**：每年約 3 集，並包含 2020-03、2022、2025 這幾個大跌時期的集數。試跑要確認：

- schema、引文通過率、分段品質
- 實際 token 數和成本，用來修正 §7.2
- 人工抽查 50 張卡：有沒有把玩笑當成信念？有沒有把聽眾的觀點當成他的觀點？

## 8. 合規與倫理

| 議題 | 做法 |
|---|---|
| 著作權 | 節目內容的著作權屬於謝孟恭，存檔 repo 的 MIT 授權只涵蓋程式碼。`gooaye/data/` 全部 gitignore，逐字稿不進 repo、不再散布。skill 只放提煉後的框架和短引文，並附 EP 出處。whatmkreallysaid.com 的使用條款要在執行前確認。 |
| 投資建議 | `CONTRIBUTING.md` 的倫理紅線要求投資類 skill 必須有明確的免責聲明，以及「不能替代專業人士」的邊界。台灣對未經許可提供個股買賣建議也有法規限制，若要公開發布，建議先確認。skill 只做框架層級的思考，不推薦個股。 |
| 冒用身分 | skill 名稱和說明都標明「非官方」；不使用節目 logo；首次啟動時聲明內容是推論。 |
| 隱私 | 不收錄家人或其他非公眾人物的細節。健康等個人話題，只取他自己定調過的價值觀。 |
| 心理健康 | 人格 skill 遇到危機訊號時要跳出角色，並轉介專業資源。 |

## 9. 失敗模式與降級

| 狀況 | 處理 |
|---|---|
| 存檔逐字稿拿不到，或授權有疑慮 | 改用官方 RSS 音檔自跑 ASR。代價是時間和 GPU，不是 API 費用 |
| 引文驗證丟卡率偏高 | 先查是不是正規化（標點、繁簡）的問題，再調 prompt，最後才考慮換模型 |
| 主題太碎（超過 100 個） | 跑第二輪合併。女媧原則是心智模型 3–7 個，寧少勿多 |
| 某個大主題一次塞不進 context | 按年份切片分別綜整，再合併 |
| 時間切分驗證不及格 | 先看輸在哪類題目：立場錯就回 S8 調整模型權重；風格錯就回 S6 和表達 DNA。最多迭代 2 輪，仍不過就在誠實邊界中標註 |
| 成本超出預期 | 已經寫好的卡片和主題檔就是中間成果，可以停在任何階段 |

## 附錄 A：卡片 schema（草稿）

```jsonc
{
  "episode": 600,
  "segments": [            // 逐字稿沒有 ## 標題時，由模型在同一次呼叫裡產出
    { "seg_id": "s3", "type": "market", "title": "汰弱留強策略" }
  ],
  "cards": [
    {
      "id": "EP0600-c07",
      "kind": "heuristic",            // belief|heuristic|market_view|self_correction|qa|story|expression|uncertainty
      "lens": "invest",               // invest|life|both
      "seg_id": "s3",
      "claim": "一句話轉述（用分析者自己的話）",
      "quote": "逐字摘錄，≤80 字，必須是逐字稿原文的子字串",
      "tone": "serious",              // serious|joking|sarcastic|hedged
      "speaker": "self",              // self|listener_question|quoting_other
      "condition": "這條規則成立的前提（沒有就填 null）",
      "market_view": null,            // kind=market_view 時填：
                                      // { subject, subject_type(index|sector|ticker|macro|asset),
                                      //   direction(bullish|bearish|neutral|holding|exited),
                                      //   horizon, rationale, invalidation }
      "qa": null,                     // kind=qa 時填：{ question_gist, answer_gist }
      "tags": ["部位管理"]
    }
  ]
}
```

實作時用 structured outputs 的嚴格模式：每個物件都要 `additionalProperties: false`，選填欄位改成 nullable。

## 附錄 B：S3 萃取 prompt 草稿

```
你是逐字稿分析員。輸入是 Podcast《股癌》某一集的逐字稿，主持人是謝孟恭。
任務：抽出能揭示「他怎麼想」的卡片，而不是摘要「他說了什麼」。

規則：
1. 只抽主持人本人表達的內容。聽眾來信的問題標 speaker=listener_question；
   他引述別人的話標 quoting_other。
2. quote 必須逐字複製逐字稿原文（≤80 字），不得改寫、合併或補字。
   找不到能支持的原文，就不要出這張卡。
3. claim 用你自己的話轉述，一句話。
4. tone 要誠實標記玩笑、反諷、誇飾，不要把玩笑當成信念。
5. market_view 只在他明確表態方向時才出；含糊帶過的不出。
6. 贊助段落一律跳過。
7. 比起「看好哪一檔」，更重要的是理由、前提，以及什麼情況下他會改變想法。
8. 寧缺勿濫：沒有符合條件的內容就輸出空陣列。
9. 如果逐字稿沒有段落標題，先輸出 segments 再輸出 cards。
```
