## 2. 發現

### 2.1 大多數集數沒有段落標題

| 年份 | 集數 | 有 `##` 標題 |
|---|---|---|
| 2020 | 101 | 0 |
| 2021 | 104 | 1 |
| 2022 | 105 | 1 |
| 2023 | 104 | 1 |
| 2024 | 104 | 0 |
| 2025 | 105 | 36 |
| 2026（至 EP700） | 77 | 69 |

不少 2021–2024 年的集數只有一個 `### QA` 標題，正文整段沒切。所以 S3 讓模型在同一次呼叫裡先分段再抽卡，這個設計是必要的。

另外，「只有 Q&A 標題」的集數目前被當成已分段，正文會整段送進去。**待改**：只要正文少於 3 個標題，就也交給模型分段。

### 2.2 手動萃取 3 集的結果

| 集數 | 背景 | 卡片數 | 引文通過 | 模型分段 |
|---|---|---|---|---|
| EP10（2020-03） | 熔斷崩盤、投資亂象 | 23 | 23 | 5 段 |
| EP255（2022-07） | 空頭、融資斷頭潮 | 43 | 43 | （有 QA 標題） |
| EP547（2025-04） | 關稅股災、二寶出生 | 32 | 32 | 11 段 |
| 合計 | | 98 | 100%（97 張完全比對、1 張模糊比對） | |

各類卡片數量：

| 分類方式 | 數量 |
|---|---|
| 種類 | belief 36、heuristic 25、story 9、self_correction 7、uncertainty 6、qa 6、expression 5、market_view 4 |
| lens | invest 69、both 15、life 14 |
| tone | serious 83、joking 8、hedged 4、sarcastic 3 |

觀察：

- **life 線偏少**：3 集裡人生卡只有 14 張。人格面的主力素材是 Q&A，而 2025 年以後的集數 Q&A 題數多很多。所以人格 skill 的證據會偏向近兩年，S8 要留意時間分布不均。
- **跨域原則已經出現**：只看 3 集，就有幾個原則同時出現在投資和人生兩邊，例如「先想最壞情況」「認輸換來睡得好」「每件事都有風險」「凡事走到極端就不好」，合計 15 張 lens=both 的卡。這支持「跨域原則就是核心模型」的設計。
- **自我修正素材很豐富**：一集就有好幾段他談自己的錯誤，例如砍掉後來大漲的股票、早期靠融資起家、第一胎時以為生小孩帶財而積極操作股期。這是 `self_correction` 卡的好來源。
- **他很少給絕對答案**：EP255 的 Q&A 他直接說自己很少給絕對答案，只給思路。這可以當成 skill 的回答原則之一（待更多集數驗證）。

### 2.3 引文驗證器

負面測試（`validate_cards.py` 對竄改過的卡）：

| 竄改方式 | 判定 |
|---|---|
| 捏造一句他沒說過的話 | 不通過，該集標為需重跑 |
| 改一個字（「沒有人」→「沒人」） | 通過，但標為 fuzzy |
| 段落編號標錯 | 通過，標為 exact_elsewhere |

改一字會通過，這是模糊門檻（90）的取捨。之後可以統計 fuzzy 卡的比例，比例偏高就調高門檻。

新增的兩個警示（只標記，不自動丟卡）：

- **privacy**：claim 或 quote 含病名、病房、學校、取名等字詞時標記。3 集只命中 1 張，而且是誤判（「投顧老師的取名」）。隱私測試集 EP547 談了大量孩子的醫療細節，手動萃取時都沒寫進卡片；API 實跑後要確認模型也做得到。
- **speaker**：引文落在聽眾來信（`>` 開頭的引用行）裡卻標成本人觀點時標記。限制：有些集數的聽眾來信是寫在「」裡，不是 `>` 引用格式，這種情況抓不到。

可以先記下的訊號（S8 再和卡片交叉確認）：

- **保留語氣約是確定語氣的 4 倍**，而且 2020 年之後明顯上升。這和卡片裡大量的 `uncertainty` 一致。
- **粗話頻率 2023 年最高，之後下降。**
- **「我」的使用率在 2023 年後上升**，可能和開場生活段變長有關。
- **英文術語密集**：nvidia、google、asic、eps、hbm、guidance、odm、pcb 等。
- **口頭禪候選**：「最後面」「跟你講」「發現說／知道說／覺得說」「跟大家分享」。

限制：

- 高頻 n-gram 前幾名多是一般連接詞，還沒有和一般中文口語語料做對照，所以「辨識度」還沒算出來。這要補一份對照語料。
- 2020 年句長明顯偏短，可能是早期逐字稿斷句方式不同，不能直接解讀為風格改變。

## 3. 成本上修

手動萃取的輸出量實測：每集約 8–15k 字元 JSON，平均每張卡約 350 字元。換算約 8–10k 輸出 token／集，加上思考 token 約 10–14k／集。計畫原本估 4–6k，偏低。

| 模型 | 單趟 S3（Batch，702 集） | 計畫原估 |
|---|---|---|
| Claude Opus 5.5 | 約 USD 95–135 | 55–80 |
| Claude Sonnet 5.5 | 約 USD 50–70 | 25–40 |
| Claude Haiku 4.5 | 約 USD 25–35 | 13–20 |

全專案因此從 USD 60–200 上修到約 **USD 90–260**。

可以降低輸出量的做法（不影響品質）：

- schema 的 `mv_*` 五個欄位只有 market_view 卡會用到，可以拆成選填物件，省下大量 `null`。
- 預估可減少 20–30% 輸出。

**以上都是推估**。實際數字要等 `s3_extract.py count` 和 20 集的 batch 跑完才算數。

## 4. 下一步

**需要你做的**

1. 在這個雲端環境設定 `ANTHROPIC_API_KEY`，或者自己在本機跑。
2. 跑 20 集試跑：
   ```bash
   cd gooaye/pipeline
   python3 s0_s1_fetch.py --eps 10 45 60 130 170 200 240 255 290 330 370 400 440 470 510 547 549 600 640 670
   python3 s2_segment.py && python3 s3_extract.py render
   python3 s3_extract.py count --model claude-opus-5-5   # 先看實際 token
   python3 s3_extract.py submit                          # 三個模型各一批，總成本估 USD 5–10
   python3 s3_extract.py collect <batch_id>              # 每個 batch 各跑一次
   python3 validate_cards.py ../data/cards/claude-opus-5-5
   ```
   20 集三個模型的估計：Opus 約 USD 3–4、Sonnet 約 USD 1.5–2、Haiku 約 USD 1。
